## 当前部署与日常启动

当前机器使用 **Windows 原生 WSLC 3.0.3.0**，不是下方的 Ubuntu Docker 入口。电脑打开 <http://localhost:9100>，手机使用二维码中的 <http://192.168.1.3:9100>。管理与重建步骤见 [当前 WSLC 部署手册](DEPLOYED-WSLC.md)。

```powershell
wslc list
wslc logs --tail 50 phone-pc-transfer
# 仅在容器已停止时启动：
wslc start phone-pc-transfer
```

当前无需手工 portproxy；未配置登录自动启动或故障自动重启。不要同时启动旧 Docker 容器争用 9100。

## 备选快速启动（Docker Engine / Compose）

目标环境：WSL 内已安装 Docker Engine 与 Docker Compose v2。以下命令在 WSL 的项目目录执行；先按[部署文档](docs/DEPLOYMENT.md)配置 NAT 转发或 mirrored 网络与防火墙，再设置手机可访问的地址。

```bash
# 将地址替换成 Windows 当前可信局域网 IPv4；不要填写 localhost 或容器 IP。
PUBLIC_URL=http://192.168.1.8:9100 docker compose up -d --build
# 如需重复启动保留配置，将 PUBLIC_URL 写入本地 .env；不要提交该文件。
docker compose ps
docker compose logs --tail=50
```

Windows 浏览器打开 `http://localhost:9100`，iPhone 扫描接收页二维码并保持 Safari 前台。若未配置 `PUBLIC_URL`，也可在接收页输入手机能访问的 HTTP 地址。批量下载为一个 ZIP 文件；收到内容后请及时复制或下载。运行时无外部资源依赖，首次安装依赖、构建或拉取镜像通常需要网络。

## 1. 目标与原则

为个人自用开发一个简单的网页工具，让 iPhone 上的文字、网址和相册图片能够方便地发送到 Windows 电脑，替代为传输内容而登录微信的操作。

- 以 Docker 镜像交付，部署在 WSL 中的 Docker Engine。
- 同一 Wi-Fi 下使用，运行时不需要互联网。
- 使用 HTTP，不引入 HTTPS、证书或公网部署。
- 手机不用安装 App；电脑通过浏览器接收。
- 优先减少操作和部署复杂度，不复刻完整 PairDrop，不扩展为公共文件分享平台。

## 2. 已确认范围

| 项目 | 要求 |
| --- | --- |
| 使用对象 | 个人及自己的设备 |
| 传输方向 | 第一版仅 iPhone → Windows 电脑 |
| 手机浏览器 | iPhone Safari |
| 电脑浏览器 | Windows Edge、Chrome |
| 内容类型 | 文字、网址、相册图片 |
| 网络条件 | 同一 Wi-Fi，设备可互相访问；无互联网仍可运行 |
| 在线条件 | 两端同时打开页面，传输时手机 Safari 保持前台 |
| 配对 | 电脑显示二维码，手机用系统相机扫描 |
| 授权 | 扫码配对授权一次，后续连续发送不逐条确认 |
| 并发范围 | 每个接收会话一次仅配对一部手机 |
| 留存 | 允许临时存储，不做持久化历史或离线收件箱 |

注意：同一 Wi-Fi 只是使用前提，不保证网络互通；访客隔离、防火墙等仍可能阻止访问。

## 3. 用户流程

1. 用户在 WSL Docker Engine 中启动容器，配置端口以及手机可访问的局域网地址。
2. Windows 用 Edge 或 Chrome 打开电脑接收页，优先使用 localhost 地址。
3. 接收页创建临时接收会话并展示二维码。
4. iPhone 用系统相机扫码，以 Safari 打开手机发送页。
5. 配对成功，二维码失效；该手机可以连续发送文字或多张图片。
6. 电脑页面展示内容、传输状态以及复制和下载操作。
7. 电脑可断开连接、重新配对、清空内容；换手机需要重新配对。

### 3.1 文字和网址

- 手机通过输入框输入或长按粘贴；不要求自动读取手机剪贴板。
- 电脑按卡片展示文字，保留中文及换行。
- 提供复制按钮；浏览器不允许复制时，允许选中并手动复制。
- 网址可以由用户主动打开，不自动跳转。
- 文字按纯文本安全展示，不将输入解释为 HTML 或脚本。

### 3.2 图片

- 手机支持一次选择多张相册图片。
- 显示发送进度，以及成功、失败状态。
- 电脑对可支持格式显示预览；不能预览的格式显示文件信息，仍允许下载。
- 提供单张下载和批量 ZIP 下载入口；批量下载已实现为一个 ZIP，不依赖浏览器连续下载多个文件。
- 不默认自动保存到 Windows 磁盘；网页收到文件与文件已下载是两件事。
- 不主动压缩或转换格式，传输浏览器实际提供的文件，不承诺取得 iPhone 相册底层原始文件。
- 不开发 HEIC 转 JPEG。

## 4. 部署与架构方案

```text
Windows Edge / Chrome（电脑接收页）
             │ HTTP，优先 localhost
             ▼
     WSL Docker Engine 中的容器
     ├─ 本地网页及全部静态资源
     ├─ 临时会话与扫码配对
     ├─ 接收文字、图片并向接收页提供状态
     └─ 图片临时存储、预览及下载
             ▲
             │ HTTP，同一 Wi-Fi
             │ Windows 局域网地址及暴露端口
       iPhone Safari（手机发送页）
```

### 4.1 架构边界

- 容器本身就是用户本机上的接收服务，并非外部中转服务器。
- 内容路径为手机 → 本机容器 → 电脑接收浏览器，不经过第三方服务。
- 不使用 WebRTC，不需要公网信令、STUN 或 TURN。
- 页面、脚本、二维码生成所需资源等均随镜像提供，运行时不依赖 CDN、在线字体或外部 API。
- 运行时离线不等于构建或首次拉取镜像不需要网络；完全离线安装时需事先准备镜像。
- 实现采用 Node.js 原生 HTTP 服务与原生 HTML/CSS/JavaScript；接收页通过轮询更新状态，容器默认监听 9100。实现选择不改变上述产品需求，具体配置见[部署文档](docs/DEPLOYMENT.md)。

### 4.2 WSL 网络注意事项

Docker 发布端口并不必然意味着 iPhone 能通过 Windows 的局域网地址访问。

[部署文档](docs/DEPLOYMENT.md)已分别说明 NAT + Windows portproxy 与 mirrored 两条路径；部署时需按实际模式确认：

1. 容器服务监听及端口发布。
2. Windows 到 WSL 的访问路径。
3. 必要的 Windows 局域网入口或端口转发。
4. Windows／适用的虚拟化防火墙规则，仅开放必要端口并限制在可信网络。
5. 先检查 Windows 本机访问，再检查另一台局域网设备访问。

二维码必须使用手机可访问的地址，不得使用 localhost、容器内部地址或错误的 WSL 内部地址。部署时允许显式配置外部访问地址，不要求实现复杂的自动网络发现。

### 4.3 HTTP 与剪贴板

普通局域网 HTTP 不具备全部安全上下文能力，不能依赖手机自动读取剪贴板。电脑优先从 localhost 打开接收页；复制操作仍需兼容失败并提供手动复制路径。不为剪贴板引入 HTTPS。

## 5. 配对与安全边界

- 使用临时、不可轻易猜测的配对凭证。
- 一个接收会话只接受一部手机，成功配对后原二维码失效。
- 成功配对的手机可以连续发送；其他手机不能仅凭处于同一 Wi-Fi 就加入已配对会话。
- 电脑可以主动断开或重新配对，并撤销旧手机继续发送的权限。
- 访问与下载需要会话授权，不能仅靠文件名访问其他会话内容。
- 页面接收任意文字、文件名时不得执行脚本；服务端校验授权、体积与数量，不能仅依赖前端限制。
- 日志不记录文字正文、图片内容或完整配对凭证。
- HTTP 不加密，不承诺抵御同网络窃听或中间人攻击；仅定位于可信家庭／个人 Wi-Fi，不应暴露到公网。
- 当前实现使用一次性配对凭证，默认 5 分钟过期；已配对发送凭证随断开、重新配对或会话闲置到期撤销。上述默认值为实现配置，而非额外需求。

## 6. 临时存储与清理

用户已确认允许临时存储；以下保留需求及实现边界，后续变更应明确记录。

- 图片优先放在 Docker tmpfs 中，不挂载永久内容目录。
- 不建立持久化历史，不提供手机先发、电脑以后再取的离线收件箱。
- 断开后短暂保留已收到内容供电脑下载；闲置 30 分钟自动清理。
- 容器重启后内容不保留。
- 提供清空已接收内容操作，释放暂存容量。
- 接收页可显式“结束接收会话”，确认后删除临时内容、撤销凭证并释放名额；忙碌时暂不允许结束。
- 空接收会话失联且无业务活动 120 秒后可回收（扫描最多再延迟 30 秒），有内容不会因关页而提前清理，仍按业务闲置期处理。轮询只记录页面存活，不延长业务闲置时间。
- 刷新页面不承诺恢复历史；界面提醒重要内容及时复制或下载。
- 应用不主动持久化内容，但 tmpfs 不能作为取证级“绝不落盘”承诺，宿主机可能使用交换空间。
- 用户已下载到 Windows 的文件不受服务清理影响。

当前实现以配对、发送、下载及显式断开／重新配对／清空等操作更新活动时间；单纯状态轮询不续期。上传、下载或清空中的会话暂不清理；定时清理最多每 30 秒检查一次，鉴权也检查过期。断开不会立即删除内容，默认自最近活动起闲置 30 分钟后失效。详见[部署文档](docs/DEPLOYMENT.md)。

## 7. 默认限制与异常处理

| 限制项 | 默认值 |
| --- | ---: |
| 单次文字 | 100,000 字符 |
| 每批图片 | 20 张 |
| 单张图片 | 50 MB |
| 每会话暂存总量 | 200 MB |

以上为服务端可配置默认值。字符按 Unicode 码点计数；MB 按十进制 1,000,000 字节换算。会话总量含文字 UTF-8 字节与图片字节；另有固定 2,000 内容条目保护限制。Compose 的默认会话数为 2（直接运行服务的默认值为 8），需与 tmpfs 和内存配额一起调整。

- 发送显示进度，以及明确的成功或失败状态。
- 发送成功表示接收服务已接收，不代表文件已下载到 Windows 磁盘。
- 连接和传输设置有限超时：服务端请求及连接空闲超时 120 秒、请求头超时 15 秒；前端图片上传／下载及 ZIP 下载上限 120 秒，普通 API 默认 15 秒（个别操作更短或为 20 秒）。超时后先查看接收箱，避免重试造成重复发送。
- 网络隔离、防火墙、地址错误等访问问题提供排查指引，不声称浏览器能够准确诊断所有底层原因。
- 失败允许手动重试，不做断点续传。
- 超出限制明确提示，允许清空后继续。
- 不无限等待，不自动切换到外部中转，不悄悄上传到第三方。

## 8. 第一版不做

- 公网部署、跨网络传输、账号系统。
- 完全复刻 PairDrop、自动列出附近所有设备。
- 永久设备绑定、多手机同时向一个会话发送。
- 电脑向手机反向发送。
- 视频、文件夹及通用大文件传输平台。
- 离线收件箱、持久化历史、断点续传。
- 自动读取剪贴板、强制自动复制或自动打开网址。
- 图片压缩、HEIC 格式转换。
- Windows 桌面客户端或开机常驻程序。

## 9. 验收标准

1. 镜像能运行于 WSL Docker Engine；按部署说明配置后，Windows Edge／Chrome 可打开接收页，iPhone Safari 可扫码访问并配对。
2. 断开互联网但保留 Wi-Fi 局域网连接时，新开页面、生成二维码、配对、传输与下载仍可完成；无外部资源请求依赖。
3. 中文、换行文字和网址显示正确，可复制或手动选中复制；网址不会自动打开，文本不会被当作脚本执行。
4. 可一次选择多张图片，进度与状态可见；受支持格式可预览，其他格式可下载。
5. 对浏览器提交的文件进行完整性验证，下载所得文件与提交给服务的文件字节一致，不以相册底层文件作为比较对象。
6. 第二部手机不能加入已配对会话；电脑重新配对后可更换手机，旧配对失效。
7. 数量、文字长度、单文件大小、会话容量限制均在服务端生效，有明确提示。
8. 断连、失败及超时有反馈，可手动重试；不调用外部中转。
9. 清空、到期清理、容器重启后，临时内容不再可通过服务取回。
10. 文档覆盖 WSL 网络入口、手机访问地址、端口与防火墙排查；不把仅 Windows localhost 可访问等同于局域网验收通过。

其中 iPhone Safari 和实际 Wi-Fi／WSL 网络互通需真机验收，不能仅凭自动化测试宣称全部通过。
